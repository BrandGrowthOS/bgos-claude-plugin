# Managed plaintext fields

The agent can request `browser_type` without `slowly` or `submit`, or `browser_fill_form` containing textbox fields. Each request needs a fresh recipient approval labeled **Enter page text**. The permission carries the original RPC hash and fixed metadata; field contents remain in the existing authenticated RPC, not the approval document.

The main-only `AgentProfileFieldInput` prepares exact current MCP snapshot handles before asking. Bounded `eN` and `fNeN` refs are accepted as syntax; the mapped native handle must still belong to the exact original Page and its main frame. There is no arbitrary selector, live locator execution, focus call or global keyboard path. The Playwright 1.64.1 bundle hash and private in-process utility APIs are qualified explicitly. A changed or unsupported dependency refuses this lane.

The clean utility world classifies visible editable native inputs and textareas using native type, autocomplete, identifying attributes, associated labels and owning-form context. Search, email, URL and telephone inputs have explicit native purposes; ordinary text and textarea fields require a recognized title, subject, search, notes, comment, message, name, company or city purpose. Bounded native labels permit generated identifiers. Password, OTP, payment, token and recovery indicators, including another control's native form labels, refuse. Unknown semantics and custom elements refuse. No field value or saved login is read.

The private one-use ticket retains the original document and nodes, full URL, native signatures and deadline. The original signed arguments, full runtime authority, selected Page, main frame, navigation generation and cancellation must remain current after the recipient answers. Every field passes the same checks before any value is set. All native value assignments run synchronously before input and change events. Page focus changes cannot redirect an assignment to another element. Main-world prototype overrides cannot replace the utility world's native setters.

A native setter or dispatch failure, document/signature interruption, or lost execution acknowledgement after a possible write is an unknown outcome. There is no rollback or retry. The Companion blocks new commands and handover in explicit recovery even after physical cleanup. Normal application listeners can observe or react to field changes. The DOM reports listener-thrown exceptions separately from `dispatchEvent`; this path does not promise transactional application handlers, trusted physical keyboard events or website honesty about field meaning.

`prepare({name,args,signal,deadlineAt})` returns an opaque capability. `execute({capability,name,args,signal})` claims it once. `cancel`, `whenDrained` and `dispose` retain physical work until the actual producer, utility execution, ticket and every handle/listener settle. Cleanup starts independently, including synchronous failures. Failed cleanup retains its private global lease and refuses subsequent admission. At most one operation per helper and eight prepared operations globally are admitted. Bounds are 32 distinct fields, 16 KiB per value, 64 KiB total and 60 seconds or the original RPC deadline. Disposal starts alongside native browser shutdown, so a held field operation cannot prevent shutdown from starting.

Global key presses, per-character typing, automatic submit, contenteditable editors, custom elements, unknown purposes, subframes and non-textbox fill fields remain unsupported. Use human handover for those cases. Passwords and security codes continue through the protected native human login flow.

`scripts/probe-browser-profile-fields.mjs` is an opt-in, disposable Linux qualification. Its permission and authority are synthetic. The actual shipped Companion plus HOAI permission composition and production rollout are separate acceptance gates.
