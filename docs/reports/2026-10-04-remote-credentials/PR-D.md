# Ship protected agent browser storage and first-use provisioning

Fresh plugin installations now include the browser host, owner login protocol, passphrase-encrypted profile vault, automatic pinned Chromium provisioning and a browser skill that teaches the agent the full workflow. The normal supervisor starts the host. The disposable Linux staging directory is only test evidence; an owner does not need to reproduce it.

The authenticated browser context is nonpersistent and separate from Chrome's native disk context. Owner unlock restores encrypted session cookies, persistent cookies, localStorage and IndexedDB. Every new browser starts locked, with ephemeral browsing until unlock. Password entries need explicit native Save consent. Existing plaintext profiles require explicit clearing consent and are never silently reopened. Vault operations and browser replacement are serialized, errors preserve prior ciphertext, and saved state includes deletions. Session storage is excluded.

Credentials cross the authenticated HOAI server as sealed, scope-bound X25519/HKDF/AES-GCM envelopes. They are decrypted on the agent machine and filled into an exact supported form. Ordinary B password typing remains refused. Filling does not submit; the owner receives a 30 second grant for one validated physical submit click. The agent skill prohibits asking for passwords, passphrases, cookies or tokens in chat or putting them in scripts, tool arguments or environment variables.

Saved data uses AES-256-GCM and an asynchronous scrypt-derived owner key, owner-only permissions, authenticated assistant/principal scope and atomic writes. The key and passphrase are never saved. This is not secrecy against a compromised HOAI server, Expo renderer, agent account or destination website. Those remain trusted during use. Known-password text redaction covers normal tool outputs and artifacts, not every transformed value, bearer token, page pixel or screenshot. Lost passphrases cannot recover saved data.

The host prefers installed Chrome/Chromium, otherwise provisions its bundled pinned revision into the user cache. Installer environment filtering excludes Chrome-specific opt-ins. No privileged operating-system package installation or sandbox disabling occurs automatically. The README and shipped skill include Linux dependency inspection and administrator setup instructions.

Validation: 124 focused Linux tests, 24 Windows security/storage tests, clean tsc --noEmit, and fifteen executable red/restore mutations. A fresh npm-packed 0.60.5 installation with empty dependency/browser caches exercised production supervisor startup, automatic download, locked credential prepare, cookie discard and full host restart. All eight required source/skill files match the final candidate. Actual remote-Linux native Save, saved-login fill, restart, wrong-passphrase refusal and restoration before fill are recorded in the companion BGOS report. Delegated final review independently reran adversarial Chromium probes and matched package hashes with no unresolved actionable findings.

This is a separate companion candidate for BrandGrowthOS/bgos-claude-plugin. It remains local for orchestrator review. Nothing was pushed, merged to main, published or changed in production.
