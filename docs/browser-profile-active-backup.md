# Agent active encrypted backup API

These new main-only modules compose the existing fixed paired HOAI client, scheduler, encrypted journal and seal worker. They are advisory best-effort backups. They cannot stop, stage, restore, readdress or activate a browser. The source document and network stay active.

## Capture

`openAgentLiveReadScope({runtime, authority, assertCurrent, protection, timeoutMs})` captures the exact original native context, pages, main frames, URLs, target IDs, loader IDs, storage keys and ledger generation. It opens only owned native CDP sessions. Its API exposes fixed readonly cookies, origin storage and final safety verification, with no caller-chosen CDP method, expression, selector or file path. It uses the existing fixed document-safety expression in isolated worlds and the existing readonly storage codec. It does not call the transfer helper whose detach failure is suppressed.

The exact original transfer qualification and activity inventory must be idle. Every historical origin must have a current qualified main document. Partitioned or unavailable origins, loading documents, credentials, unfinished authentication, unsaved forms, navigation, replacement frames, changed credential version or context loss skip capture. All original page frames are checked before capture and again immediately before sealing. This is a best-effort read while scripts keep running, not a transaction across website state.

A logical deadline never frees native physical capacity. Every attempted listener and CDP session is retained until all physical commands settle and all independent removals/detaches succeed. A failed cleanup keeps a private lease and refuses later scopes for that runtime. At most four original runtime scopes may be held.

`AgentLiveBackupCapture` captures request recipients and its transient key copy before native setup, uses `NativeLiveBackupCapture`, verifies safety again, and runs the actual `BackupSealWorker`. It independently drains the read scope, capture and seal worker. Caller-owned retained keys are not zeroed. Owned transient content-key byte copies are zeroed after use. This does not claim that immutable JavaScript strings, website memory or Node KeyObjects can be reliably zeroed. A cleanup failure latches unknown and cannot be reset by public flags or another capture.

## Scheduling and recipients

`AgentActiveBackup` accepts the exact original runtime/full authority, enrolled endpoint keys, original pairing owner/ID, locally signed peer-identity reader, synchronous current-key reader and immutable extras reader. It uses production debounce 60000ms. `start()` schedules restored state; `notify()` accepts existing command/navigation/storage hints. One owned deadline also covers storage-only changes without DOM or IDB instrumentation. Its first automatic eligibility is 60000ms after start; each newly confirmed snapshot advances eligibility to confirmation plus 60000ms. The timer follows that absolute eligibility and the separate automatic-attempt cooldown, rather than adding another debounce when a periodic tick lands just before confirmation eligibility. Timer waits stay within 1..60000ms even after a wall-clock jump; actual attempts still check eligibility and use the existing global physical bounds. There is no new DOM polling, arbitrary evaluation or faster backup interval. Pause and disposal clear the owned timer synchronously; only a positively drained same-source resume re-arms it. An absolute due time survives short command pauses. Once due, the next same-source idle resume starts the normal scheduler capture immediately, so repeated commands cannot reset the debounce forever. Only a newly confirmed snapshot advances that due time. A separate 60000ms automatic-attempt cooldown survives pauses, so skipped or unknown outcomes cannot cause a fresh coordinator read on every short command resume. An exact owned automatic attempt cancelled before entering its context may release its unused cooldown only after all independent pause cleanup succeeds. Coalesced manual work, entered context, failed cleanup and unknown outcomes retain their bound. Explicit read-only reconciliation remains available independently. There is no overlap or new upload retry when an old journal outcome is unknown.

Each capture first obtains signed v2 `endpointContext` from HOAI. The complete current admitted set must pass local policy before reading the retained content key. The own source must be the exact original agent identity, authority grant, pairing owner and pairing ID. Every other recipient must match a locally signed reviewed identity and fresh metadata must identify a desktop owned by the acting account with no pairing. Unknown or replaced identities, another agent, changed role or owner, missing source, duplicate recipient and changed grants skip the entire backup. There is no partial encryption or guessed grant. Existing v1 peer pins contain identities only; additional-agent recipient roles require a future explicit review format and are unsupported here.

The client metadata is advisory. Local signed pins independently establish identity review. Historical local pins verify retained journal signatures; only the complete fresh approved set receives encryption. The key object, bytes, epoch, full original source and metadata deadline are checked across capture, journaling and upload.

An encrypted journal is written before one upload attempt. A possible write or unconfirmed prepared journal is never uploaded again automatically, including after helper replacement. `reconcile()` performs exact read-only server reconciliation and may mark the local journal confirmed. It cannot activate a writer or convert a live backup into a stopped checkpoint.

`pause()` closes scheduler admission synchronously, cancels pending client work and waits for positive physical drain. `start()` after pause requires that receipt and the same active source. `dispose()` closes admission before independently draining capture, client, scheduler and journal; unknown cleanup retains the private exact runtime reservation. Native runtime shutdown must be started independently by the Companion before awaiting backup disposal.

## Integration and proof boundary

The Companion creates one helper only after the exact runtime is activated and its HOAI RPC binding is proved. Its stable journal directory binds the original profile, acting account and endpoint rather than a boot/runtime ID. Existing native completed requests and navigation are dirty hints; at most 32 original page listeners are retained. The normal 60-second hint also covers storage-only changes and page churn beyond that listener bound.

Every ordinary command pauses and positively drains original backup reads before native work. The same source resumes only after command cleanup and removal from the command set. Handover and retirement drain before native finalization. Disconnect and daemon shutdown fence scheduler admission synchronously. Revocation and emergency shutdown start native disposal independently of held backup creation or disposal. All attempted listeners are removed independently; failed removal or physical drain retains private unknown admission and activity.

Original context, engine, endpoint, extras, full authority, acting scope and pairing must remain unchanged. Backup capture also requires no pending file, field or download work. The existing signed `hoai_browser_status` reports bounded backup state and can reconcile an unknown upload read-only. An unknown upload with positive cleanup does not block ordinary browser commands, and no command resends it. Unknown physical cleanup does block command and handover admission.

The original Companion runtime factory supplies the required synchronous `assertTransferAllowed` callback. It binds the original native context, runtime, endpoint identity, full authority, recipient and pairing scope, and cached current active writer grant. Commands, live permissions, file or field work, unknown physical cleanup and uncertain authority refuse the read. Ordinary accepted stopping remains valid; daemon closing requires the already accepted exact private retirement permit. Disposal invalidates that preparation even if public runtime flags are restored. This callback does not replace the independent native document, credential, HTTP and transport inspections.

Unit tests use synthetic native CDP and coordinator metadata, with actual seal/journal worker execution and real private temporary files. The 60000ms debounce test uses a synthetic clock. Shipped Linux automatic backup after a real 60 seconds, complete fresh HOAI recipients, active original browser, durable directory fsync and positive process/container cleanup remain separate required acceptance gates. No production records are used.
