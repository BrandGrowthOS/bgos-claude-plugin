# Learnings index (bgos-claude-plugin)

Durable gotcha / regression notes for the connector. Read the relevant one before touching the code it warns about. Format per note: Date, Context, Gotcha / Pattern, How to apply next time, Regression guard. Started 2026-08-25 with the zero-terminal lifecycle work; the BGOS app repo keeps its own index at `docs/learnings/INDEX.md`.

| Learning | What it covers | Regression guard |
|---|---|---|
| [cli-classifiers-pin-captured-output](cli-classifiers-pin-captured-output.md) | `claude plugin update` help text says "restart required to apply"; the real success line is `Plugin "hoai" updated from A to B for scope user. Restart to apply changes.` A classifier pinned on help text would have turned every successful update into a garbage verdict and a reinstall ladder. | `test/plugin-cli.test.ts` golden lines + `test/fixtures/fake-claude.mjs` prints the byte-exact captured output |
| [marketplace-cache-dir-is-a-git-clone](marketplace-cache-dir-is-a-git-clone.md) | Claude Code installs a url/git-source plugin by cloning into `<config>/plugins/cache/hoai/hoai/<version>/` and LEAVES `.git` there, pinned to the release tag. The clone-path git self-updater (default ON) ran on marketplace installs too and could fast-forward Claude Code's cache dir to `origin/main` behind its bookkeeping. Gate: never arm the git updater when `INSTALL_METHOD === 'marketplace'`. | `test/self-update.test.ts` static guard (`server.ts never arms the git self-updater on a marketplace install`) |
| [channel-only-sessions-write-no-transcript](channel-only-sessions-write-no-transcript.md) | A channel-only session (no typed user turn) writes NO transcript under `<config>/projects/`, so `--resume <pinned>` is rejected on the spot. The old rule "we launched it, so it exists" cost every restart a doomed launch plus a NEW pinned id. The transcript on disk decides on every relaunch; no transcript means `--session-id <same id>` again. | `test/hoai-supervise.test.ts` (`marker relaunch of a session with NO transcript creates it again by the SAME id`) |
| [dev-channels-gate-on-marketplace-installs-and-the-windows-console](dev-channels-gate-on-marketplace-installs-and-the-windows-console.md) | The "Loading development channels" warning gates MARKETPLACE launches too on CLI 2.1.241, no settings key silences it, and its default is exit. On Windows there is no `expect`; the helper attaches to the launcher's console, reads the live (alternate) screen buffer, and presses Enter only once the gate marker is on screen. Spawn it `detached: false` or it exits 0 having done nothing. | `test/hoai-supervise.test.ts` (`win32 gate helper source: only ever presses Enter after the gate marker is on screen, never blindly`, `win32GateHelperArgs`) |
| [windows-watcher-service-task-scheduler-api](windows-watcher-service-task-scheduler-api.md) | `schtasks /Create /SC ONLOGON` is admin-only (EPERM unelevated); the Task Scheduler API via PowerShell `Register-ScheduledTask -AtLogOn` works unelevated; HKCU `Run` is the fallback. The bundle ships `install-task.ps1` + `run-hidden.vbs`. | `test/watcher-service.test.ts` (win32 spec, refusal ladder) |
| [directory-marketplaces-and-the-version-field](directory-marketplaces-and-the-version-field.md) | A marketplace added from a local DIRECTORY is not copied under `<config>/plugins/marketplaces/`; `known_marketplaces.json.installLocation` is the only correct way to find its `marketplace.json`. And "latest" is only observable when the plugin entry declares `version` or its `ref` is a semver tag; a bare branch ref reads as unknown (up to date). | `test/plugin-cli.test.ts` (`observeMarketplaceInstall` follows installLocation; `readMarketplaceLatest` version / ref rules) |
| [two-state-roots-and-the-silent-probe](two-state-roots-and-the-silent-probe.md) | Two plugin state roots: `~/.bgos-agent/<id>/` (launcher: supervisor, marker, session-id, recipe, probe) and `~/.bgos-plugin-state/<id>/` (daemon: cursors, `channel-live.json`). The liveness marker refreshes only on a tool call, so after a routine restart nothing proves the session hears the channel until someone speaks; the watcher writes `probe-requested.json`, the daemon asks the session to call `channel_ack`, and only `lastLiveAt > restartedAt` counts. | `test/agent-verify.test.ts`, `test/channel-ack.test.ts`, `test/boot-hello.test.ts` |
| [windows-test-baseline](windows-test-baseline.md) | On a Windows box the pristine suite has 13 node + 1 bun failures (0600 / symlink / shell / path artefacts); CI is Ubuntu and green. Read the runner's `failing tests:` block, never a grep. A fresh clone needs `core.autocrlf=false`. | none (environment), the list of the 14 names is in the note |
