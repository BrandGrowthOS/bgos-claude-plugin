# Managed download runtime hooks

On Linux the Companion prepares the reviewed private download manager for the original exact runtime authority before loading or launching Chromium. It retains creation through actual settlement and disposes a late manager after account or preparation loss. Other agent platforms keep managed downloads disabled and report `managed_downloads_unavailable`; ordinary local HOAI browsing is unaffected.

The main-only runtime binding requires the manager's original private class brand and exact full authority. Forged objects, prototype copies and serialized values cannot enable downloads. It invokes the original manager checks, activity, drain and disposal methods, so replacing public activity or public health methods does not clear uncertainty. Shared health is a private method: startup and guarded EOF finalization may use a healthy original runtime without accepting new downloads, while new events and commands additionally require active recipient admission, a connected socket, no uncertainty, no revocation and no closing state. The Runtime stores its binding as an immutable property. No tool or renderer receives this capability or its private path.

Before launch, Runtime consumes the one-use launch options containing the explicit private downloads directory. It enables `acceptDownloads` only with that genuine binding, then binds the original empty context to the immutable independently owned native process-stop capability before the first seed or page. The stop callback calls that process capability directly and does not await Runtime disposal. The existing native target observer and inactive-stage network protection remain unchanged.

The Engine factory passes the same exact manager callback before `Engine.start`. Events observed by both the early context listener and Engine coalesce by original Download object. The callback cannot retarget to another Runtime or replacement preparation. File listing receives the same private manager, preserving the reviewed opaque receipt, conversion and explicit recipient consent channel.

Runtime preflight, transfer inspection and finalize refuse an in-flight or uncertain download before destroying pages. Companion commands refuse an uncertain manager independently of mutable public activity. Activity and command drains include original manager work. Ordinary disposal and emergency termination start native stop and quarantine cleanup independently, attempt all sibling cleanup, and retain failures rather than reporting a false successful stop.

The focused tests use real manager objects and real temporary files with an explicitly synthetic Linux UID/mode projection on Windows. They verify original scope across held preparation, launch/bind capabilities, movement refusal, native-first cleanup and the actual pinned MCP Engine factory. Actual sandboxed Chromium downloads, overflow and slow cancellation, positive process/file cleanup and composed encrypted release require separate native acceptance receipts.
