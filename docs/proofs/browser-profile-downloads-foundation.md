# Managed download quarantine foundation

The new manager prepares one private agent-owned quarantine before browser launch and binds one original empty context. This commit leaves Runtime, Companion and the browser-host factory unchanged. The separately reviewed hooks must enable ordinary managed downloads later.

One receiving download per runtime and four per process share bounded private inventory with screenshots and PDFs. Accepted files are limited to 25 MiB, four per runtime and sixteen per process, with a 120-second download deadline and a two-second cancellation grace. The manager retains the exact cancellation Promise even after native stream acknowledgement. Unknown cleanup starts the independently owned browser stop and retains capacity; disposal and drain wait every physically pending cleanup, copy and newly started stop Promise. Ready receipts and converted artifacts are opaque capabilities with no tool-visible path.

The explicit file-list action converts ready quarantine receipts through owned no-follow file I/O. Conversion retains both cleanup owners of the same inventory entry. Existing recipient consent still precedes encrypted HOAI file release. No website click permission is reused as file-release consent, and listing a file sends no file bytes.

Six touched suites passed 63 tests with zero failures or skips. Full plugin TypeScript checking passed. The tests use real temporary file I/O and inodes, with an explicitly synthetic Linux UID/mode projection on Windows. Existing file crypto and staging exercise encrypted offer/upload flow through synthetic server responses. These are foundation tests, without a native browser or cross-machine download claim. Independent source review closed the final manager at ABFD52BB; the parent also ran 53 tests across its exact four-path selection and the final three held-cancellation cases separately.

Twenty-two isolated executable-copy drills printed the changed production lines and produced direct assertion failures. Each restored the exact copied bytes and passed the same selected test. They cover launch/bind claims, exact context and page, private raw directory, active admission, receiving and retained capacity, accepted size, wall deadline, original copy context, copy-before-delete, cancellation-before-delete, cancellation grace after stream acknowledgement, physical disposal and stop, independent cleanup owners and explicit artifact conversion. Shared source bytes never changed. The JSON receipt contains every changed line and red/restore/green output hash.

The first copy-before-delete trial stayed green because its fixture observed deletion before asynchronous verification could run. That trial is excluded. The fixture now observes the exact cleanup verification entry while the copy is held, and all twenty-two final drills passed. A standalone held-cancel fixture initially exited before its unreferenced product timer ran; a bounded referenced fixture observation fixed the test without changing product timers. That diagnostic is also excluded.

The quarantine is private plaintext on the agent machine. It is not encrypted while Chromium writes it. Chromium may transiently overshoot the observed size threshold, and two conversion operations can temporarily duplicate up to 50 MiB. The 400 MiB limit describes accepted retained content in one process, not an OS disk quota. Abrupt crashes can leave private orphan directories; new processes never adopt them or reconstruct consent, and those old files are outside in-memory limits. Actual sandboxed browser downloads, overflow/slow cancellation, positive native process/file cleanup and composed encrypted release remain separate acceptance work.
