# Managed companion foundation proof

The plugin source now composes recipient-scoped setup discovery, OS-protected endpoint identity reload, explicit session readiness, native runtime preparation, typed HOAI command fetch/result, encrypted local journals and reviewed source pins. Installation alone does not enroll, grant, acquire a writer or invent a recipient. All feature network traffic uses HOAI.

The final focused aggregate passed 110 tests with zero skips, including exact byte verification of all nine pure shared modules against committed BGOS source `2cf1b495a683a19e69d4a583c84842d363660f2e`. Plugin `tsc --noEmit` passed. The existing host, download and trust suites separately passed 50 tests with zero skips; their real Chromium fixture uses a synthetic relay and legacy profile namespaces.

## Executable mutations

Each direct case printed its changed executable line, produced a failing behavioral test, restored exact original bytes and then passed the touched test. A syntax error was not accepted as proof.

- [Client and agent stopped-head stage](browser-profile-agent-stage-client-mutations.json): 18 earlier cases, each retaining its exact source hash. These cover pairing-only headers, recipient and readiness binding, bounded physical requests, no write replay and the separate one-use stopped-head stage path.
- [Private state and peer pins](browser-profile-companion-state-mutations.json): six cases cover current pairing origin, recipient identity, immutable catalog contents, capacity and a post-link revocation tombstone.
- [Current companion and lifecycle](browser-profile-companion-lifecycle-mutations.json): 19 cases cover separate recipient keys, unknown versus revoked status, one active status operation, old reply isolation, permission refusal, source-pin/readback barriers, namespace downgrade, retained physical stop reservations, queued launch admission, delayed ownership readiness, explicit shutdown status and post-pause form inspection.
- [Native disposable copies](browser-profile-companion-native-mutations.json): three real Chrome cases suppress dirty-form detection, skip group termination or replace immutable process ownership with a mutable field. Each failed, then the restored exact copy passed its full native check. No installed plugin or real profile was changed.

The native form probe uses sandboxed Chrome `155.0.8059.39`. It checks pristine normalized range, color, invalid number/date, radio and select defaults, method-shadowing names, uppercase credential tokens, bounded inventory, isolated evaluation while paused, a post-inspection edit race, and same-document preservation on refusal. Only booleans leave the document inspection.

The shutdown probe uses a fresh private Chrome runtime. Activation, empty extras and the literal-loopback transport qualification are fixtures. It verifies the real browser PID owns its process group and retains its native start token. A normal dirty-page stop preserves the same input and ticking page with no checkpoint. Explicit process termination returns actual Node exit status1, proves that owned group has zero members, writes zero stopped receipts and reports recovery required. The helper's green test status0 means this expected child exit1 was observed, not a successful saved shutdown.

## Review and delivery boundary

Independent read-only reviews closed the scoped state/pin lifetime findings and process lifecycle findings after repairs. Failed pairing disposal remains tracked and prevents replacement. Emergency termination waits for the exact native ownership capability and cannot promote an unresolved launch to a successful stop.

This is not proof of a full companion, Linux keyring, mounted HOAI server, main browser host and human two-machine handover in one run. The keyring provider and HTTP readiness were qualified separately. The composed disposable install remains required before delivery.

Managed actions needing recipient-scoped permission currently refuse. A same-daemon explicit End session remains closed until a separate recipient-scoped open intent is implemented. An unknown network result pauses new agent admission and preserves memory; only a verified current revocation disposes that runtime. No timeout, historical readiness or local journal creates failover authority.

Saved cookies and login bundles are encrypted locally and in checkpoints. An approved destination and its OS operator can inspect plaintext while using it. Encryption does not hide credentials from an approved machine or recall keys and data it previously received. Source-pin review is explicit and separate from background consent and site permission.
