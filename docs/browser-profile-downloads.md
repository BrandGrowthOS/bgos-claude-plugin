# Managed browser download quarantine

This foundation is separate from the existing legacy browser download store and its owner/card gates. It does not grant a website permission, choose a sharer or accept a tool-supplied path. Reviewed Runtime launch/context and Companion lifetime hooks bind this capability before browser startup. The native cancellation proof is recorded separately from encrypted recipient release.

`AgentProfileDownloads.create` binds one immutable exact profile authority, an original context checker and an active-admission checker. It prepares an exclusive generated child directory through the existing private Linux file-area proof. `launchOptions()` claims one launch before its first await and returns the explicit private `downloadsPath`. `bind({context, stopBrowser})` claims one empty original context before its first await, installs its listener before any bootstrap or restored page, and retains only the caller's existing independently owned stop capability. It creates no page or context and grants no URL access. Managed Chromium must keep `acceptDownloads:false` unless this capability is present.

Only events from that exact context and page, with the pinned Playwright-owned GUID artifact under the explicit directory, can enter quarantine. Duplicate events coalesce by original Download object. Admission permits one receiving download per runtime and four per process. A failed admission fences the manager and starts the original owned browser stop once. A finite 120-second wall timer and bounded 100-millisecond observations cancel stalled or oversized downloads. Exactly one original `failure()` read is physically retained and accepts only `null` for success or a nonempty failure string. One original monotonic and real wall budget of at most two seconds starts at the first cancellation, or at a failed terminal result if cancellation was not issued. It covers the original cancellation, terminal read and positive file-absence proof without resetting. An independent timer starts owned browser stop if any of those steps remains unresolved, including a held filesystem read. The original operations and inventory remain reserved until physical settlement, and uncertainty cannot be cleared by a stop acknowledgement. No logical timeout releases capacity.

Playwright's delete API is used only for successful streams. A failed Chromium download can acknowledge cancellation before asynchronously removing its partial file, while `download.delete()` rejects the failed artifact. After both original acknowledgements, the manager observes only its exact original GUID final and partial paths within the same grace budget. Each pass rechecks the original directory; every extant path must retain regular-file, single-link, owner and observed-inode proof. Oversized bytes may be observed for cleanup but cannot be accepted. Both paths must positively return `ENOENT`. The manager never unlinks a failed stream, retries delete or adopts a different path. Invalid terminal results, replaced paths or persistent bytes fence the manager and retain capacity.

A successful completion must pass exact UID, private directory, mode, regular-file, single-link, inode and size checks. Only the manager can issue the opaque completed receipt. Neither metadata nor tools receive a path. An explicit `hoai_browser_files` call converts ready receipts into artifacts by an exclusive no-follow copy, with bounded zeroed buffers and original full context checks before and after awaits. It preserves the original download expiry. Copies retain the original Promise and handles until settlement. There is no public method to adopt an arbitrary source path.

Downloads and screenshots/PDFs share four retained slots per exact runtime and sixteen per process. Each accepted file is at most 25 MiB, for at most 400 MiB of accepted retained content. A shared reservation has independent source and destination cleanup owners: source deletion cannot release an unresolved destination, and destination cleanup cannot release an unresolved raw source. Failed cancel, close, delete, listener removal or owned-stop proof retains a private uncertainty fence and capacity. Disposal owns its original Promise before any await; drains wait all physically pending cleanup and newly started stop work, while settled uncertainty remains reserved separately. The existing two-operation artifact I/O limit permits at most two conversion copies, with up to 50 MiB of temporary raw/destination duplication. Chromium may also transiently write beyond the observed 25 MiB threshold before cancellation physically settles. This is an acceptance and retained-content bound, not an operating-system disk quota or a promise of zero transient overshoot.

The quarantine contains private plaintext on the agent machine while Chromium downloads and while the explicit release is pending. OS ownership and mode checks protect this directory; this module does not encrypt Chromium temporary files. After an abrupt daemon or machine crash, a private orphan directory can remain on disk. A new process never adopts those files, reconstructs their opaque receipts or treats them as consent, and its in-memory process limits do not account for old crash orphans. Positive ordinary cleanup is proved separately; an OS disk quota and crash-orphan recovery are outside this foundation.

Completed downloads become opaque artifact tokens only. Existing explicit recipient file consent, encrypted HOAI offer/upload/claim and native save apply unchanged. Creating or listing an artifact sends no file bytes. A website click gate is never borrowed to release a download, and a file-release consent never permits a website upload. Ordinary downloads remain outside sign-in capsules and never open automatically or synchronize a folder.

The focused manager tests use real temporary file I/O and inodes with an explicitly synthetic Linux UID/mode area on Windows. They cover one-use launch/binding/receipts, one receiving slot, shared retention, finite frozen-clock cancellation, overflow deletion, held observations and copies, context loss, independent browser stop, opaque artifact conversion and both sides of cleanup uncertainty. The file runner test exercises the actual shared crypto/staging client through a synthetic HOAI server response and proves offer-before-consent, then exact encrypted bytes. The fake native file owner serializes its own stop/cancel/delete removals to avoid concurrent Windows `unlink` conflicts; real errors still propagate. The [separate native proof](proofs/browser-profile-download-terminal-cleanup.md) exercises actual sandboxed Chromium 153 and 156 for completion, slow cancellation and overflow, including positive process and file cleanup. Cross-machine download release remains a separate composed acceptance requirement.
